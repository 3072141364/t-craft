# 研发流程预设提示词

接到 feat/bugfix 后,按阶段复用以下提示词(方括号填实际内容)。⚠️ 标记的 skill 是占位 TODO,暂未实现--触发时会告知"未实现",可先用提示词里的思路手动跑。

整条流程:① 头脑风暴 -> ② 方案设计 -> ③ 实现 -> ④ 审计/评估 -> ⑤ 提交 -> ⑥ 沉淀。方案、评估报告、卡片、参考表都进 Obsidian。

## ① 头脑风暴 / 需求深挖

> 我接到一个 [feat / bugfix] 需求:[一句话描述]。先用 brainstorm ⚠️ 和我深挖:真实意图、约束、边界、风险、验收标准;同时用 obsidian-kb 查 vault 里相关的旧方案(按 summary 判相关性:无关跳过 / 弱相关简读 / 强相关精读 ⚠️ vault-query),看有没有可复用的设计、有没有踩过的坑。产出需求要点(一句话目标 + 约束 + 验收标准 + 相关旧方案链接)。

## ② 方案设计

> 基于需求要点,用 obsidian-kb 把本次方案写到 vault(`项目/[项目名]/方案/[方案名].md`):背景 -> 目标 -> 候选方案 -> 权衡 -> 决策 -> 后续。需要架构 / 流程 / 泳道图时联动 fireworks-tech-graph 生成 PNG,存 `项目/[项目名]/附件/` 并嵌入 `![[图.png]]`。代码仓库只留指针(`> 方案见 Obsidian: [[方案名]]`)。

## ③ 实现

> 按方案逐步实现。每步:make-shortcut 跑构建 / 测试(`make build` / `make test`),code-format 格式化(`make format`);遇 bug 用 code-intelligence 查调用链 / 影响。实现一段就跑一次测试,别堆到最后。

## ④ 审计 / 评估 / 测试

> 实现完,先 `/code-review` 做双轴审查(Standards 规范 / Spec 需求),确认无问题、无范围蔓延;再用 eval-report ⚠️ 产出评估 / 测试报告:逐条确认需求达成、用 code-intelligence 评估回归影响、列测试结论(跑了什么 / 通过情况 / 覆盖了什么)。报告存 vault `项目/[项目名]/评估/`。保证实现了需求且不影响其他功能。

## ⑤ 提交

> 审查 + 评估都过,用 git-flow 提交:格式化 -> 更新 CHANGELOG -> 询问版本号 -> commit -> 推送(确认)。

## ⑥ 沉淀(卡片 + 表格)

> 把本次可复用的设计 / 思路 / 方案,用 obsidian-kb 沉淀成知识卡片(决策 / 模式 / 踩坑 / 事实),存 `卡片/`,双链回方案;新的约定 / 概念 / 数据更新到 vault 速查表(标签速查表 + 约定表 + 概念表)。

---

**省 token 提示**:查 vault 时,让 AI 先按标签 + summary 判相关性,无关跳过、弱相关只读 summary、强相关才精读全文(待 vault-query ⚠️ 实现后自动化)。
