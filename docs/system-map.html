  • 影响面评估 — /tcraft-code-review impact:改动影响哪些调用链/模块,不破坏其他功能。开发完第一步。

the vault

Obsidian vault 模型

vault 只放项目 / 论文 / 技术 / 周报;跨项目可复用知识提炼进 skill 仓库,模板也在 skill 仓库,不从 vault 取。

vault/
  projects/# 项目开发
    <项目名>/# wiki · workflow · assets · reference.md
      requirements/<需求名>/
        prd · adr · test · review · progress.md
  papers/# 一论文一卡 + reading-list
  tech/<主题>/# 技术学习笔记
  weekly/周记 <YYYY>-W<ww>.md # 三流汇总,只链 progress
  misc/# 零散卡,平铺靠标签
  archive/# 已完成项目
  cards.base # 动态视图:按类型 / 进行中需求 / 论文 / 按项目
the principles

五条设计原则

01 · 调度链

dev-flow 识别阶段 → 激活 skill → 更新 progress → 流转,每个环节都有 skill 和文档归位。

02 · 渐进披露

SKILL.md 只留要点,细则全在 references(31 篇),用到才读。

03 · 状态真源唯一

需求状态只在 progress.md;周报记事情、progress 记状态,不互相复制。

04 · 通用知识回流

跨项目可复用知识去项目化后沉淀进 skill 仓库,随插件跨机器生效。

05 · 两档验证

轻档(影响面/冒烟)看方向,重档(全量测试/全量评估)看细节,前后各一道轻档兜底。
