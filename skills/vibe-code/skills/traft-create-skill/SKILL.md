# traft-create-skill 技能

创建新技能：按**原则**产出符合规范的技能——模板结构（`templates/skill-template.md`）、命名规范、**禁绝对路径**、实现原则（**能用脚本实现的功能优先脚本化，减少 token 消耗**）、交付校验。

**职责边界**：
- 负责：技能创建的原则指导——结构/命名/实现/路径/校验。
- 不负责：填充后的内容质量（作者按原则补全）、技能功能实现。超出边界直接说明，不硬接。

## 1. 触发条件（TRIGGER）

| 场景 | 触发信号(关键词/典型句式) | 是否触发 |
| --- | --- | --- |
| 新建技能 | "新建一个技能"、"创建 skill"、"想加个新技能" | 触发 |
| 查模板/原则 | "技能模板在哪"、"创建技能的原则" | 触发 |
| 完善已有技能 | "按模板优化 xxx"、"检查这个技能规范吗" | 触发（指导 + 校验） |
| 实现功能 | "帮我实现 xxx 功能" | 不触发，转交对应技能 |
| 闲聊/泛泛提问 | "随便聊聊" | 不触发，交给默认回复 |

## 2. 规则（RULES）——创建技能的原则

### 2.1 务必执行(ALWAYS DO)
1. **结构原则**：SKILL.md 按 `templates/skill-template.md` 六节组织——职责边界 / 触发表（正例≥3、反例≥1）/ 规则三段（ALWAYS/NEVER/CONDITIONAL）/ 知识底座（含「约定变更时同步更新本节」）/ 工作流（每步带完成标志）/ 输出规范（固定格式 + 字段要求 + 自检）/ 示例（好/差）。
2. **渐进式披露**：SKILL.md 控制在 500 行以内为宜；大块参考资料（超过 300 行）拆到 `references/`，用到再读，文件较长时开头加目录；一个技能涉及多个领域时按领域分文件存放，只读相关的那篇。
3. **命名原则**：技能名精准概括技能职责，见名知意；命名风格与同级技能保持一致（沿用同级统一前缀）；description 写「做什么（简述）+ 何时触发（触发关键字）」。
4. **禁绝对路径**：技能文档与脚本内一律相对路径或 `skill://<name>/...` 引用。
5. **实现原则（脚本优先）**：技能涉及可执行操作（转换/生成/统计等）时，**能写脚本就用脚本实现**（放 `scripts/`，文档相对引用），agent 直接调脚本而不是每次手写逻辑；脚本 `python3 -m py_compile` 通过。
6. **写作风格**：指令用祈使句；多讲"为什么"、少堆硬性"必须"（说明理由比强约束更有效）；示例按"输入/输出"成对呈现。（精确输出模板由模板的 5. 输出规范标准化承载）

### 2.2 禁止执行(NEVER DO)
1. 不在技能里写绝对路径（目录/脚本/引用）。
2. 不把可脚本化的操作留在文档里当「步骤说明」——能用脚本就脚本化。

### 2.3 条件执行(CONDITIONAL)
- 需要的输入：技能名、所在目录、description（做什么 + 触发词）。
- 缺失时：目录/描述不明 → 先与用户确认，不猜。

## 3. 知识底座（CONTEXT）

- **模板**：`templates/skill-template.md`（六节结构 + 每节写作说明）
- **命名**：技能名精准概括职责、见名知意；与同级技能命名风格保持一致（沿用统一前缀）；仓库约定见 AGENTS.md
- **结构约定**：
  ```text
  skill-name/
  ├── SKILL.md       # 必填: frontmatter(name/description 必填, 有依赖加 compatibility) + 正文
  ├── scripts/       # 可选: 确定性/重复性任务用可执行脚本
  ├── references/    # 可选: 按需加载的参考资料(渐进披露)
  └── assets/        # 可选: 输出用的模板/图标/字体
  ```
- **依赖声明**：技能有必需工具/依赖（外部 CLI、库、外部技能等）时写入 frontmatter 的 `compatibility` 字段；无依赖则省略
- **约定变更时同步更新本节。**

## 4. 工作流程（WORKFLOW）

### Step 1: 定技能信息
- 动作：确认技能名（按目标仓库命名约定）、目录（相对路径）、description（做什么 + 触发词）。
- 完成标志：三项明确。

### Step 2: 按模板起草
- 动作：参照 `templates/skill-template.md` 起草 SKILL.md——先写职责边界与触发表，再补规则/知识底座/工作流/输出规范/示例。
- 完成标志：六节齐全，无遗留占位。

### Step 3: 脚本化实现（按需）
- 动作：可脚本化的操作写进 `scripts/`（相对引用），文档只留「调脚本」的短说明；`python3 -m py_compile` 通过。
- 完成标志：脚本就位且编译通过，文档不重复脚本逻辑。

### Step 4: 校验
- 动作：`grep '/Users/' <技能目录>` 无绝对路径；触发表正反例齐全；脚本编译通过。
- 完成标志：校验全绿。

## 5. 输出规范（OUTPUT SPEC）

### 5.1 固定格式
```text
## 技能
<dir>/SKILL.md（六节结构）
## 实现
<脚本化说明: scripts/ 与相对引用;无脚本则说明原因>
## 校验
绝对路径: 无 | 脚本编译: 通过 | 触发表: 正例N 反例M
```

### 5.2 字段要求

| 字段 | 写作要求 |
|----|------|
| 技能 | 目录与结构完整性 |
| 实现 | 脚本优先原则的执行情况 |
| 校验 | 绝对路径/编译/触发表三项 |

### 5.3 交付前自检
- [ ] 六节结构齐全，正反例触发表
- [ ] 可脚本化操作已脚本化（相对引用）
- [ ] 无绝对路径（grep 通过）
- [ ] 脚本 py_compile 通过（如有）

## 6. 示例

### 6.1 好的示例
**输入**：帮我建个技能，解析任务耗时日志，统计各阶段平均耗时，还能转成 perfetto 看
**输出**：
```text
## 技能
skills/<plugin>/skills/trace-stats/SKILL.md（六节结构）
- 命名: trace-stats（贴合职责；同级技能均带统一前缀）
- description: 解析任务耗时日志,统计各阶段平均耗时;触发——"统计任务耗时"、"各阶段平均"、"转 perfetto 看时间轴"
## 实现
scripts/parse_stats.py: 日志解析+统计逻辑脚本化（脚本优先），文档只留一行调用说明；py_compile 通过
## 校验
绝对路径: 无 | 脚本编译: 通过 | 触发表: 正例4 反例2
```

### 6.2 差的示例
**输入**：帮我建个技能，解析任务耗时日志
**输出**：跳过模板手写 200 行 SKILL.md；解析逻辑写成文档里的多段步骤说明（不脚本化）；文档写死 `/Users/xxx/...` 绝对路径。
（违反 2.1①④⑤——模板结构、脚本优先、禁绝对路径）
