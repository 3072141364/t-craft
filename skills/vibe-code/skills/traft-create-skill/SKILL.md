# traft-create-skill 技能

创建新技能：按**原则**产出符合规范的技能——模板结构（`templates/skill-template.md`）、命名规范、**禁绝对路径**、实现原则（**能用脚本实现的功能优先脚本化，减少 token 消耗**）、注册同步、交付校验。

**职责边界**：
- 负责：技能创建的原则指导——结构/命名/实现/路径/注册/校验。
- 不负责：填充后的内容质量（作者按原则补全）、技能功能实现。超出边界直接说明，不硬接。

## 1. 触发条件（TRIGGER）

| 场景 | 触发信号(关键词/典型句式) | 是否触发 |
| --- | --- | --- |

## 2. 规则（RULES）——创建技能的原则

### 2.1 务必执行(ALWAYS DO)
1. **结构原则**：SKILL.md 按 `templates/skill-template.md` 六节组织——职责边界 / 触发表（正例≥3、反例≥1）/ 规则三段（ALWAYS/NEVER/CONDITIONAL）/ 知识底座（含「约定变更时同步更新本节」）/ 工作流（每步带完成标志）/ 输出规范（固定格式 + 字段要求 + 自检）/ 示例（好/差）。
2. **命名原则**：vibe-code 插件内 `traft-*` 前缀；其他位置按目标命名空间；description 写「做什么 + 何时触发（路由靠它）」。
3. **禁绝对路径**：技能文档与脚本内一律相对路径或 `skill://<name>/...` 引用；交付前 grep `/Users/` 确认无残留。
4. **实现原则（脚本优先）**：技能涉及可执行操作（转换/生成/统计等）时，**能写脚本就用脚本实现**（放 `scripts/`，文档相对引用），agent 直接调脚本而不是每次手写逻辑——减少 token 消耗；脚本 `python3 -m py_compile` 通过。
5. **注册同步**：新技能进 README 技能表（更新技能数）、`traft-guideline` 路由表（如适用）；bump `package.json` + marketplace 版本。

### 2.2 禁止执行(NEVER DO)
1. 不在技能里写绝对路径（目录/脚本/引用）。
2. 不把可脚本化的操作留在文档里当「步骤说明」——能用脚本就脚本化。

### 2.3 条件执行(CONDITIONAL)
- 需要的输入：技能名、所在目录、description（做什么 + 触发词）。
- 缺失时：目录/描述不明 → 先与用户确认，不猜。

## 3. 知识底座（CONTEXT）

- **模板**：`templates/skill-template.md`（六节结构 + 每节写作说明）
- **命名**：vibe-code 插件内 `traft-*`；其他位置按目标命名空间
- **结构约定**：技能 = `SKILL.md` + 可选 `scripts/`（脚本实现）+ 可选 `templates/`（模板）
- **注册点**：`README.md` 技能表、`skills/vibe-code/README.md`、`traft-guideline` 横切表、`package.json` + `.omp-plugin/marketplace.json` 版本
- **约定变更时同步更新本节。**

## 4. 工作流程（WORKFLOW）

### Step 1: 定技能信息
- 动作：确认技能名（traft-*）、目录（相对路径）、description（做什么 + 触发词）。
- 完成标志：三项明确。

### Step 2: 按模板起草
- 动作：参照 `templates/skill-template.md` 起草 SKILL.md——先写职责边界与触发表，再补规则/知识底座/工作流/输出规范/示例。
- 完成标志：六节齐全，无遗留占位。

### Step 3: 脚本化实现（按需）
- 动作：可脚本化的操作写进 `scripts/`（相对引用），文档只留「调脚本」的短说明；`python3 -m py_compile` 通过。
- 完成标志：脚本就位且编译通过，文档不重复脚本逻辑。

### Step 4: 校验
- 动作：`grep '/Users/' <技能目录>` 无绝对路径；触发表正反例齐全；脚本编译通过。
- 完成标志：校验全绿。

### Step 5: 注册同步
- 动作：README 技能表加行（更新技能数）、`traft-guideline` 路由表（如适用）；bump `package.json` + marketplace 版本；提交推送。
- 完成标志：注册完成，版本已 bump。

## 5. 输出规范（OUTPUT SPEC）

### 5.1 固定格式
```text
## 技能
<dir>/SKILL.md（六节结构）
## 实现
<脚本化说明: scripts/ 与相对引用;无脚本则说明原因>
## 校验
绝对路径: 无 | 脚本编译: 通过 | 触发表: 正例N 反例M
## 注册
README 技能数 <N>→<M> | 版本 <v1>→<v2>
```

### 5.2 字段要求

| 字段 | 写作要求 |
|----|------|
| 技能 | 目录与结构完整性 |
| 实现 | 脚本优先原则的执行情况 |
| 校验 | 绝对路径/编译/触发表三项 |
| 注册 | 技能数与版本号实际值 |

### 5.3 交付前自检
- [ ] 六节结构齐全，正反例触发表
- [ ] 可脚本化操作已脚本化（相对引用）
- [ ] 无绝对路径（grep 通过）
- [ ] 脚本 py_compile 通过（如有）
- [ ] README/guideline/版本已同步
