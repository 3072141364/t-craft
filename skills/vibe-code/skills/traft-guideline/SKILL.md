# traft-guideline 技能

traft（全称 t-craft）技能组导航入口：维护研发流程六阶段路由表，接到开发任务按阶段激活对应技能；询问 traft 相关问题时帮助选择技能。

**职责边界**：
- 负责：路由——判断当前阶段、激活对应技能、推进状态提示；解释 traft 是什么。
- 不负责：执行任一阶段的具体工作（由对应技能执行）、知识库文档增删改（`traft-obsidian`）。超出边界直接转交，不硬接。

## 1. 触发条件（TRIGGER）

| 场景 | 触发信号(关键词/典型句式) | 是否触发 |
| --- | --- | --- |
| 技能咨询 | "traft是什么？"、"有哪些技能" | 触发 |
| 路由请求 | "我想用traft做XXX"、"接下来该干嘛" | 触发 |
| 启动研发流程 | "开始做个功能"、"走研发流程"、"我现在在哪个阶段" | 触发 |
| 具体阶段执行 | "帮我实现"、"review 一下" | 不触发，直接由阶段技能接管 |
| 闲聊/泛泛提问 | "随便聊聊"、"你怎么看" | 不触发，交给默认回复 |

## 2. 规则（RULES）

### 2.1 务必执行(ALWAYS DO)
1. **阶段以 progress.md 为真源**：当前阶段优先从需求的 progress.md 状态判断；没有需求文件夹时从对话语境推断。
2. 每阶段结束把 progress.md 的 status 推进到下一阶段，并提示进入下一阶段。
3. 路由表见 3.1/3.2，按表激活对应技能。

### 2.2 禁止执行(NEVER DO)
1. 不跨阶段跳转（如未评审直接发布）。
2. 不替用户决定阶段归属——需求含糊先交 `traft-requirements` 深挖。

### 2.3 条件执行(CONDITIONAL)
- 需要的输入：需求上下文（progress.md / 对话）。
- 缺失时：无需求文件夹 → 从对话语境推断阶段，并如实说明推断依据。

## 3. 知识底座（CONTEXT）

### 3.1 研发流程路由（开发线）

| 阶段 | 做什么 | 激活技能 | 产出 |
|------|--------|---------|------|
| ① 头脑风暴 | 搞清楚需求是什么、要做什么、**不做什么** | `traft-requirements`（查 vault 旧方案走 `traft-obsidian`） | 需求要点，落 prd.md「需求」部分 |
| ② 方案设计 | 整理并落盘方案 | `traft-code-docs`（要配图走 `traft-code-graph`） | prd.md「方案」部分 + adr.md |
| ③ 实现 | 写代码（落地 prd） | `traft-code-implement`（主）；`traft-code-intelligence`（查证）、`traft-code-comment`（注释）；遇 bug 走 `traft-code-debug` | 代码 + adr.md |
| ④ 验证 | 先评审：影响面 -> 全量 -> 修复 -> 冒烟 | `traft-code-review`（双轴审查）；测试 / 审查记录落盘走 `traft-code-docs` | test.md + review.md |
| ⑤ 发布 | 提交 -> 合并主分支 -> peer review -> 上线 | `traft-code-git` | 无 |
| ⑥ 沉淀 | 提炼可复用内容进 skill 仓库 | `traft-obsidian`（wiki / 卡片 / 踩坑） | wiki / 卡片 / 可复用技能 |

### 3.2 横切技能（按需，不限阶段）

| 技能 | 何时用 |
|------|--------|
| `traft-code-intelligence` | 写 / 改 / 理解 / review 代码时的查证路由（gitnexus / LSP / read 工具组） |
| `traft-code-debug` | 排查问题、定位根因（③④ 常驻） |
| `traft-code-graph` | 技术图（架构 / 流程 / 泳道 / UML / C4） |
| `traft-code-make` | 项目命令体系路由：格式化 / 测试 / lint / 构建 / 清理，一条 make 命令 |
| `traft-perfetto-trace` | 通用事件可视化：多任务并发/事件耗时 → ui.perfetto.dev（耗时/进展/重合度 + 查询 SQL） |
| `traft-create-skill` | 创建新技能：脚本生成骨架 + 内置模板 + 注册同步（元技能） |

### 3.3 其他线

| 线 | 技能 | 定位 | 触发场景 |
|------|------|------|----------|
| 知识库 | `traft-obsidian` | vault 入口 | 知识库文档增删改查，按内容路由到 traft-code-docs / research / weekly |
| 调研 | `traft-code-graph` | 图表绘制 | 文章思路、实验流程图绘制 |
| 日程 | `traft-todos` | 周级临时小任务 | Tasks checkbox 记 todo（勾掉即完成）、生成周报、结转下周 |
| 日程 | `traft-task` | 项目任务与需求进展 | 建任务、查任务、每周评估、月归档 |

## 4. 工作流程（WORKFLOW）

### Step 1: 判断意图
- IF 咨询 traft 是什么/技能清单 → 直接介绍 3.1/3.2/3.3，完成。
- IF 开发任务/阶段询问 → 继续 Step 2。
- 完成标志：意图明确（咨询 vs 路由）。

### Step 2: 确定当前阶段
- 动作：读需求 progress.md 的 status（状态真源）；无需求文件夹从对话语境推断。
- IF 新需求无文件夹 → 阶段 ①，激活 `traft-requirements`。
- 完成标志：当前阶段确定。

### Step 3: 激活技能
- 动作：按 3.1 路由表激活对应技能，说明本阶段做什么与产出。
- 完成标志：技能已激活，阶段产出明确。

## 5. 输出规范（OUTPUT SPEC）

### 5.1 固定格式
```text
当前阶段: <①~⑥>
激活技能: <技能名>
本阶段做什么: <一句话>
产出: <对应文档/产物>
```

### 5.2 字段要求

| 字段 | 写作要求 |
|----|------|
| 当前阶段 | 来自 progress.md 真源；无则说明推断依据 |
| 激活技能 | 用 3.1 路由表对应技能，不自行发明 |

### 5.3 交付前自检
- [ ] 阶段判断有依据（progress.md 或对话语境）
- [ ] 激活技能与路由表一致，产出明确
- [ ] 未跨阶段跳转

## 6. 示例

### 6.1 好的示例
**输入**：开始做个新功能：给订单加导出
**输出**：
```text
当前阶段: ① 头脑风暴
激活技能: traft-requirements
本阶段做什么: 搞清楚需求是什么、要做什么、不做什么
产出: 需求要点，落 prd.md「需求」部分
```

### 6.2 差的示例
**输入**：开始做个新功能：给订单加导出
**输出**：直接跳到实现阶段激活 `traft-code-implement`。
（未过 ① 需求深挖，跨阶段跳转——违反 2.2）
