# 注释纪律：非必要不注释

写/改/审代码时按此判断该不该注：

1. **非必要不注释**：先改名、再重构，注释是最后手段——别拿注释给坏代码打补丁。
2. **见名知意**：函数/类/变量命名自解释优先；命名说不清的先改名，能靠命名说清楚的不加注释。
3. **必须注释的例外**（只写代码说不出来的信息，不复述代码）：
   - **对外接口**：功能、参数/返回/副作用，保证读者知道怎么用；
   - **trick 逻辑**：非显然的绕行、隐含业务约束、复杂算法，解释"为什么"这么写。
4. 零信息量注释（"处理数据""优化性能"）、复述代码的注释，写了不如不写。

写法规范（语言风格、结构化 TODO/FIXME 标记、示例）见 `skill://traft-code-comment`。
