# 代码异味基线(Fowler《重构》ch.3)

Standards 轴的固定基线--即使项目没写规范,也按这 12 味查。每味:**是什么 -> 怎么修**。两条约束:

- **项目规范覆盖基线**:项目文档明确认可的做法,即使基线会标,也压下不报。
- **永远是判断题**:每味是带标签的启发式("可能 Feature Envy"),不是硬违规;工具(linter / 类型检查)能查的跳过。

逐味(匹配 diff 时标"可能 X"并引对应 hunk):

- **Mysterious Name(神秘命名)**--函数 / 变量 / 类型名看不出它做什么、装什么。-> 改名;取不出诚实的名字,说明设计浑浊。
- **Duplicated Code(重复代码)**--同一种逻辑形状在改动里出现多处。-> 抽出共享形状,两处都调它。
- **Feature Envy(依恋情结)**--某方法更多地伸手到别的对象的数据里,而非自己的。-> 把方法搬到它羡慕的数据上。
- **Data Clumps(数据泥团)**--同样的几个字段 / 参数老是一起出现(该诞生一个类型)。-> 捆成一个类型,传它。
- **Primitive Obsession(基本类型偏执)**--用基本类型 / 字符串顶替一个该有自己类型的领域概念。-> 给概念一个小类型。
- **Repeated Switches(重复 switch)**--对同一类型的 switch / if 链在改动里反复出现。-> 多态替换,或两处共用一个 map。
- **Shotgun Surgery(霰弹式修改)**--一个逻辑改动被迫在多个文件里散改。-> 把一起变的东西收进一个模块。
- **Divergent Change(发散式修改)**--一个文件 / 模块因多种不相关原因被改。-> 拆成每个模块只为一个原因而变。
- **Speculative Generality(投机性泛化)**--为 spec 没有的需求加了抽象 / 参数 / hook。-> 删掉,内联回去直到真有需求。
- **Message Chains(消息链)**--长的 `a.b().c().d()` 导航,调用方不该依赖。-> 在第一个对象背后藏一个方法。
- **Middle Man(中间人)**--类 / 函数几乎只是转发。-> 砍掉,直接调真目标。
- **Refused Bequest(被拒继承)**--子类 / 实现者忽略或覆盖大部分继承来的东西。-> 弃继承,用组合。

judgement call,不是硬违规;项目规范覆盖;工具能查的跳过。
