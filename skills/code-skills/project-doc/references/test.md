# 测试文档(test)

> project-doc 的附属文档:测试计划与结论(test.md)怎么写。写测试计划(实现前)、整理测试结论(实现后)、阶段④补测试报告时读本文。落点 `projects/<名>/requirements/<需求名>/test.md`,模板在 skill 仓库 `assets/templates/test.md`。

## 定位

一份需求**测了什么、怎么测、结果如何**的记录,给 peer review 与回归用。测试计划(实现前)与测试结论(实现后)在同一文件,是 prd「AI 须知·测试决策」的执行证据。

## 骨架

```markdown
---
title: <需求名>
type: feat
project: <项目名>
status: ③实现
date: <日期>
tags: []
---

## 测试计划(实现前)
- 测哪些模块、什么 seam(优先既有、最高 seam、理想一个)。
- 关键用例列表(正常 / 边界 / 异常)。

## 测试结论(实现后)
| 跑了什么 | 通过 | 覆盖 | 缺什么 |
|----------|------|------|--------|

## 结论
可发布 / 需修。
```

## 规则

- **计划先行**:prd 的「测试决策」在这里展开成具体用例,实现前与用户确认。
- **只测外部行为**:不测实现细节(与 karpathy 目标驱动一致:用例指向可验证目标)。
- **结论如实**:跑了什么、通过与否、覆盖了什么、缺什么,逐项列,不美化。
- **执行命令**:`make test` / `make lint`(code-guidelines 附属文档 make-shortcut 路由),工具能查的不手工验。
- **与 review 分工**:test.md 是测试证据;review.md 综合审查 + 达成确认给出「可发布/需修」结论。
