# README 写作细则

> git-guidelines 的附属文档:README 的内容结构与写作要点。写 README、更新 README、新项目初始化 README 时读本文。

## 定位

README 是项目的**门面**:用户在仓库页第一眼看到的就是它。回答三个问题——**这是什么、为什么有它、怎么快速跑起来**。其余内容按项目规模取舍,不贪多。

## 结构(从必需到可选)

```markdown
# <项目名>

一句话说明:做什么、解决什么问题。(+ 徽章:CI / 版本 / 覆盖率,有 CI 就放)

## 快速开始
最小可跑路径:安装 -> 一条命令跑起来 -> 看到什么算成功。
新人照抄就能跑,别假设环境。

## 使用 / 示例
(有 CLI / 库 / API 时)核心用法 + 最小示例。示例是「能直接复制跑」的。

## 项目结构
(目录一多就值得写)模块/包一句话职责。

## 配置
(有配置项时)环境变量 / 配置文件说明,给默认值。

## 贡献
指向 CONTRIBUTING,不复制内容。
```

## 写作要点

- **一句话开场**:`<名> 是一个…,用于…`。别用「这是 XX 项目」占位废话。
- **快速开始是正文**:README 80% 的读者只想要这个。写得比文档任何一节都具体。
- **命令用代码块**:复制即用,不给截图不给省略号。
- **以实际内容为准**:结构/命令/徽章从项目文件读,不凭记忆;改动跑一遍再更新。
- **与 CLAUDE.md 分工**:README 写给人和 CI;项目对 AI 的约定(命令、分支、规范文档位置)在 CLAUDE.md,不重复塞进 README。
- **与 CHANGELOG 分工**:版本历史在 CHANGELOG,README 不记 changelog。

## 反例

| 反例 | 问题 | 改法 |
|------|------|------|
| 只有徽章 + 简介,没有快速开始 | 新用户无从下手 | 补最小可跑路径 |
| 快速开始假设「你已装好 X」 | 不是最小路径 | 把装 X 也写进去 |
| 示例带省略号 / 伪代码 | 不能复制跑 | 完整可跑的最小示例 |
| 把团队约定堆进 README | 应属 CONTRIBUTING / CLAUDE.md | 移走,留指针 |
