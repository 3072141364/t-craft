# 应用型 UI 设计(工具 / 后台 / 仿真 / 本地 App)

> **场景**:你做的主要是「app」——仿真平台、后台数据管理平台、本地工具界面。这类 UI 的设计目标与品牌展示页**相反**:密度、清晰、状态、效率 > 品牌记忆点。本参考讲怎么把工具 UI 做好;品牌营销页才走 `design-language.md`。

## 为什么工具 UI 是另一套玩法

| 维度 | 品牌展示页(design-language) | 应用 / 工具 UI(本参考) |
|------|------------------------------|------------------------|
| 目标 | 讲故事、留印象 | 高效完成一个任务 |
| 信息 | 少而精 | 多而密 |
| 关注点 | hero、排版、气质 | 表格、表单、状态、快捷键 |
| 评判标准 | 好不好看 | 好不好用、扫读快不快 |

**74 款风格库只能借「气质」**(配色/字体基调),**交互骨架必须靠设计系统**。做工具时以本参考为主,需要品牌感才去翻风格库。

## 1. 组件基底:先选一个设计系统

选一个当「骨架」,别混用两套组件。按你的场景:

| 基底 | 特点 | 适合 |
|------|------|------|
| **[shadcn/ui](https://ui.shadcn.com)** | 复制粘贴式组件,代码在你手里、token 全控、暗色一键;React + Tailwind 生态 | **默认首选**(本地工具 / 仿真,要掌控力) |
| **[Ant Design](https://ant.design)** | 中后台组件最全(表格/表单/级联/树),企业后台成熟 | **后台数据管理平台优选** |
| Mantine / MUI | 组件多、内置暗色 / Material 风格 | 备选,看团队栈 |

**选型三问**:① 表格复杂度?(重表格 → TanStack Table 或 antd Table)② 要不要暗色?(shadcn/Mantine 顺手)③ 团队熟不熟 Tailwind?

## 2. 工具 UI 的 token 系统

token 不是「品牌色板」,是「干活用的调色板 + 密度尺度」:

- **中性色为主**:内容区大块中性色(灰/白/暗),品牌色只做强调与主操作。数据密集界面别让彩色打架。
- **状态色固定语义**:`success / warning / danger / info` 有固定映射、全站一致——错误一眼可辨,不临时发明颜色。
- **密度尺度两档**:`comfortable / compact`。工具默认 **compact**(行高/字号/间距收紧),长时盯屏可切 comfortable。
- **暗色是标配**:工具类 UI 的暗色不是可选项是必选项(夜间/长时间/演示)。**从第一天就双主题设计**,别后补。

## 3. 交互骨架:高频模式

- **数据表格**:虚拟滚动(大量行)、列冻结/排序/筛选、行内编辑、批量操作。选型 TanStack Table。
- **表单**:标签位置取舍、校验时机(失焦 vs 提交)、错误内联展示、保存态(保存中 / 已保存 / 失败)。
- **状态三件套**:每个数据区都要有 **loading / empty / error** 三态——这是工具 UI 和营销页最大的差别:营销页永远满,工具页天天空。
- **暗色 + 键盘**:焦点可见、快捷键、命令面板(Cmd+K)。
- **可扫读性**:层级少而硬、数字右对齐、标签稳定、删除要确认但别处处确认。

## 4. 结合本 skill 其他线

- 写 React 组件时对照 [`react-performance.md`](react-performance.md) —— 表格/列表尤其注意瀑布流与重渲染。
- 需要品牌感 / 营销页时才走 [`design-language.md`](design-language.md)(74 款风格库)。
- 事后 [`ui-review.md`](ui-review.md) 审查可访问性与 UX。
- 设计决策(为什么选这套密度/暗色)值得记 adr,走 `project-doc`。

## 5. 落地:项目自己的「工具版 DESIGN.md」

不复制营销页的 DESIGN.md,写一份工具版:中性色 token + 状态色映射 + 密度尺度 + 组件清单(用了 shadcn/antd 哪些)+ 暗色变量。放进项目根,后续迭代全站一致。
