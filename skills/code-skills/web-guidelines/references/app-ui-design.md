# 应用型 UI 设计(工具 / 后台 / SaaS / 本地 App)

> **场景**:你做的主要是「app」——SaaS 平台、后台数据管理平台、本地工具界面。这类 UI 的设计目标:密度、清晰、状态、效率 > 视觉记忆点。本参考是 web-guidelines 的主线,一切界面任务从这里进。

## 工具 UI 的设计逻辑

| 维度 | 应用 / 工具 UI(本参考) |
|------|------------------------|
| 目标 | 高效完成一个任务 |
| 信息 | 多而密 |
| 关注点 | 表格、表单、状态、快捷键 |
| 评判标准 | 好不好用、扫读快不快 |

**交互骨架靠设计系统**(shadcn / antd),不靠风格仿造。工具 UI 的「好看」是密度、层级、一致性,不是装饰。

## 1. 组件基底:先选一个设计系统

选一个当「骨架」,别混用两套组件。按你的场景:

| 基底 | 特点 | 适合 |
|------|------|------|
| **[shadcn/ui](https://ui.shadcn.com)** | 复制粘贴式组件,代码在你手里、token 全控、暗色一键;React + Tailwind 生态 | **默认首选**(本地工具 / SaaS 平台,要掌控力) |
| **[Ant Design](https://ant.design)** | 中后台组件最全(表格/表单/级联/树),企业后台成熟 | **后台数据管理平台优选** |
| Mantine / MUI | 组件多、内置暗色 / Material 风格 | 备选,看团队栈 |

**选型三问**:① 表格复杂度?(重表格 → TanStack Table 或 antd Table)② 要不要暗色?(shadcn/Mantine 顺手)③ 团队熟不熟 Tailwind?

## 2. 工具 UI 的 token 系统

token 不是「品牌色板」,是「干活用的调色板 + 密度尺度」:

- **中性色为主**:内容区大块中性色(灰/白/暗),品牌色只做强调与主操作。数据密集界面别让彩色打架。
- **状态色固定语义**:`success / warning / danger / info` 有固定映射、全站一致——错误一眼可辨,不临时发明颜色。
- **密度尺度两档**:`comfortable / compact`。工具默认 **compact**(行高/字号/间距收紧),长时盯屏可切 comfortable。
- **暗色是标配**:工具类 UI 的暗色不是可选项是必选项(夜间/长时间/演示)。**从第一天就双主题设计**,别后补。

## 3. 交互骨架:高频模式

- **数据表格**:虚拟滚动(大量行)、列冻结/排序/筛选、行内编辑、批量操作。选型 TanStack Table。
- **表单**:标签在输入框**上方**(不用 placeholder 代替标签,永远不用);helper 文字进 markup;错误文字在输入框下方内联展示;校验时机(失焦 vs 提交)全局统一。表单各元素(输入框/占位文本/焦点环/错误文字)对区块背景都要过 WCAG AA 对比度。
- **状态三件套**:每个数据区都要有 **loading / empty / error** 三态——这是工具 UI 和营销页最大的差别:营销页永远满,工具页天天空。loading 用**贴合最终布局形状的骨架屏**,不用通用转圈;empty 指明怎么填充;error 内联说清哪里错、怎么修。
- **按钮纪律**:文字与背景过对比度(WCAG AA);标签单行不折行,过长就缩短文案而非挤压宽度;`:active` 给轻微位移/缩放模拟物理按压;图标用图标库(Phosphor/Tabler 等)统一一套 + 全局统一线宽,不手绘 SVG,不用 emoji 当图标。
- **暗色 + 键盘**:焦点可见、快捷键、命令面板(Cmd+K)。
- **可扫读性**:层级少而硬、数字右对齐、标签稳定、删除要确认但别处处确认。
