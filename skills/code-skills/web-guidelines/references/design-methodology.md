# 前端设计方法论

> **来源**:提炼自 [anthropics/skills](https://github.com/anthropics/skills) 的 `skills/frontend-design`(Anthropic 官方)。本参考吸收其方法论,按 t-craft 约定重写;原文见该仓库。

把自己当成一家小工作室的设计主理人——这家工作室给每个客户做「一眼就认得出是谁家」的视觉身份。客户刚否掉过模板化的提案,为「有主见的观点」付费:为这份 brief 做**刻意的、有观点的**配色、字体、布局选择,并冒一个能自圆其说的审美风险。

## 0. 先钉住主题

如果 brief 没定死产品/主题,先自己定:说出一个**具体主体**、它的**受众**、这个页面的**单一职责**,并明确你的选择。如果记忆里有用户偏好、在做的项目、你以前做过的设计,拿来做线索。**主体自己的世界**(它的材料、器物、行话、工具)才是独特选择的来源。全程用 brief 的真实内容与真实主体去构建,不套壳。

## 1. 设计原则

- **Hero 是论点**:网页开场放主体世界里最有代表性的东西——标题、图片、动画、现场演示、交互瞬间,取最适合的形式。别默认「大数字+小标签+支撑数据+渐变强调」这套模板答案,除非那确实是最好的选择。
- **字体承载个性**:展示字体与正文字体要刻意配对,不是任何项目都会顺手抓的那几款。定清晰的层级(字重/字宽/字距)。让字体处理本身成为设计里值得记住的部分,而不是内容的中立容器。
- **结构即信息**:结构手段(序号、eyebrow、分隔线、标签)应该编码内容的真实关系,不是装饰。很多通用设计爱用 01/02/03 编号,但只有当内容真是序列(流程、时间线,顺序携带读者需要的信息)时才该用。加结构手段前先质疑它是否成立。
- **动效服务主题**:想清楚动画在哪儿、为什么服务主体——载入序列、滚动触发、hover 微交互、氛围。一次编排好的时刻,比零散特效更有力。但少即是多:多余的动画会强化「这是 AI 生成的」观感。
- **复杂度匹配愿景**:极繁方向需要精致执行;极简方向需要间距、字体、细节的精确。优雅=把选定的愿景执行到位。
- **文案即设计材料**:brief 常常没有真实内容,文案得你来写。文案能像设计本身一样让页面显得模板化。见下文「设计中的文案」。

## 2. 识别并绕开「AI 默认三样式」

当前 AI 生成的设计扎堆于三种外观,它们本身都可能合理,但那是**默认值不是选择**,而且与主体无关:

1. 暖米色背景(≈`#F4F1EA`)+ 高对比衬线标题 + 赤陶橙点缀;
2. 近黑背景 + 单一亮酸绿或朱红点缀;
3. 报纸式排版:发丝分隔线、零圆角、密集报纸栏。

**处理**:brief 定死视觉方向就严格照做(brief 的话永远优先,哪怕它就要这三种之一)。哪里留了自由轴,**别把自由花在这三种默认上**——像一个被雇来的人,在「做自己擅长的」和「拿每个项目当实验场」之间找平衡。

## 3. 两遍法流程

**第一遍——规划**(在动手前):基于 brief 做一份紧凑的设计计划,四件套:

- **配色**:4–6 个具名 hex 值的调色板。
- **字体**:2+ 个角色(克制的有个性展示字体、互补正文、工具字/数据字)。
- **布局**:布局概念,用一句话散文 + ASCII 线框来构思和对比。
- **Signature(签名元素)**:这个页面会被记住的那个独特元素,以恰当方式体现 brief。

**第二遍——审查计划再构建**:把计划对着 brief 审一遍——**如果任何一部分读起来像「给任何类似页面都能产出的通用默认」,就改掉它**,并说明改了什么、为什么。确认设计计划的相对独特性之后,才动手写码,严格照修订后的计划走,每个颜色/字体决策都从计划推导。

写码时小心 CSS 选择器优先级:`.section` 这类类型选择器与 `.cta` 这类类选择器容易互相抵消(常见于区块间 padding/margin)。尽量在思考里完成规划和迭代,有较高把握才给用户看想法。

## 4. 克制与自我批评

- **大胆只花在一处**:让签名元素成为唯一被记住的东西,周围保持安静与纪律,砍掉任何不为 brief 服务的装饰。不冒风险本身也是风险。
- **质量底线不声张**:响应式到移动端、可见键盘焦点、尊重 reduced-motion。这些是无须宣布的基础。
- **边做边自我批评**:环境支持就截图自审——一张图顶一千个 token。参考 Chanel 的建议:出门前照镜子,摘掉一件配饰。若有余力,记下试过什么的笔记,供后续 pass 参考。

## 5. 设计中的文案

界面里的字只有一个目的:**让人更容易理解,因此更容易使用**。文案是设计材料,不是装饰。

- **从用户那一侧写**:按人控制/认得的东西命名,绝不按系统怎么搭来命名——人管理的是「通知」,不是「webhook 配置」。说清楚做什么,别推销。具体永远好过机灵。
- **默认主动语态**:控件说清点了会发生什么——「保存更改」,不是「提交」。一个动作全程保持同一名字:按钮叫「发布」,toast 就该说「已发布」。界面词汇是用户导航的路标,一致性能让用户学会在系统里走动。
- **失败与空态是方向,不是情绪**:说清哪里出错、怎么修,用界面的语气而非人的语气。错误不道歉、不含糊。空屏是行动的邀请。
- **语气口语化、调准**:朴素动词、sentence case、无废话,音调匹配品牌与受众。每个元素只干一件事:标签就做标签、示例就做示例,没有偷偷身兼数职的。
