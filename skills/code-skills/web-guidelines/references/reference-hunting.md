# 找参考 / 仿造(参考图 → 设计语言 → token)

> **场景**:用户看中一个风格想照着做——丢来一张截图、一个图片 URL、或说「做成 XX 那样」。本参考把「看别人的设计」变成「自己的 token」,再喂给 ⑤ 应用型 UI(`app-ui-design.md`)或 ④ 品牌设计语言(`design-language.md`)执行。

## 三条来源路径

| 来源 | 怎么做 | 何时用 |
|------|--------|--------|
| ① **用户给截图 / 图片 URL**(最可靠) | Read 读图(视觉)直接分析 | 最常用——看中什么就丢图 |
| ② **官网 / 线上产品** | 用户点开 style 索引里的 `url`,或直接拉该站 DESIGN.md | 有明确目标站点 |
| ③ **文字搜索** | WebSearch 找风格文章 / 图集,对能抓的来源 WebFetch 取图 | 只有模糊方向 |

> **别硬抓画廊站**:Dribbble、saaslandingpage 等设计画廊全是 JS 渲染 + 反爬,headless 抓不到(实测空壳 / 403)。页面抓不到没关系——**图能拿到就能仿**,走 ① 让用户给图。

## 核心流程:读图 → 提取 → 确认 → 实现

1. **取图**:用户给图片 URL 就下载下来 Read;给截图直接用;给站点就建议用户截图或开官网。
2. **读图提取设计语言**(视觉逐项过一遍):
   - **配色**:主色 / 强调色 / 中性色 / 状态色的具体 hex,明暗两套
   - **字体**:展示 / 正文 / 工具字角色与气质(sans / serif / mono、字重)
   - **布局**:栅格、间距节奏、区块层级(侧栏 / 顶栏 / 内容区结构)
   - **组件风格**:按钮 / 表格 / 表单 / 卡片——圆角、边框、阴影、密度
   - **细节**:动效、图标风格、暗色切换、特殊质感
3. **整理成「设计语言清单」给用户确认**(不擅自开工):
   ```
   ▸ 配色  主 #xxx · 强调 #xxx · 中性 #xxx / #xxx(暗色)
   ▸ 字体  展示 XX · 正文 XX · 工具 mono
   ▸ 布局  左侧栏 + 顶栏 + 内容表格区,间距 16 / 24
   ▸ 组件  圆角 8 · 细边框 · 无阴影 · compact 密度
   ```
4. **token 化落地**:把确认的语言转成 token(中性色 / 状态色 / 密度 / 暗色变量),按 `app-ui-design.md` 的骨架实现。
5. **沉淀**:通用设计语言写进项目自己的 `DESIGN.md`(工具版),后续迭代照它走。

## 仿造边界

- **仿「风格 / 语言」**:配色逻辑、布局、字体气质、组件样式 → 放心做。
- **不碰「具体资产」**:别人的 logo、图片、图标、某张成品图 → 不抄,用 token 重建。
- 用户给的图若是某品牌产品,仿到「气质」为止,不加对方商标。

## 与其他线的关系

- 提取到的设计语言,按场景喂给 ⑤ 应用型 UI(`app-ui-design.md`)或 ④ 品牌设计语言(`design-language.md`)。
- 写实现时对照 ② `react-performance.md`;做完用 ③ `ui-review.md` 审查。
