# 论文笔记写法(note)

> paper-study 的附属文档:paper.md 论文卡怎么记。精读论文、写论文笔记时读本文。模板在 skill 仓库 `assets/templates/paper.md`。

## 定位

一篇论文一张卡(`papers/<论文名>.md`),记**为什么读、讲了什么、和我有什么关系、哪里存疑**——让读过的论文变成可检索、可复用的东西,而不是读完整理夹里的 PDF。

## 骨架

```markdown
---
title: <论文标题>
card_type: 论文
authors: 
year: 
venue: 
status: 在读          # 待读 / 在读 / 已读
tags: []
related: []          # 相关论文 [[...]]
source:              # 链接 / DOI
---

## 为什么读
动机:想解决什么问题、验证什么假设。

## 核心内容
- **问题**:要解决什么
- **方法**:怎么做(关键思路 / 模型 / 实验)
- **结果**:主要结论 / 数字

## 与我的关联
- 接 [[projects/<名>]] 项目?接 [[tech/<主题>]] 技术?
- 可复用的方法 / 思路(提炼进 skill 仓库?)

## 批判 / 待验证
存疑点、局限、下一步。
```

## 四节的写法

- **为什么读**:读之前的动机(为什么这篇值得读)。写"当时在解决什么问题"。
- **核心内容**:用自己的话复述问题/方法/结果,不抄 abstract。方法给关键思路 + 一笔带过的细节,够日后回忆。
- **与我的关联**:这篇接我手上的什么——项目、技术、另一篇论文?可复用的思路标出来(能否提炼进 skill 仓库)。
- **批判 / 待验证**:存疑、局限、没看懂要回来查的点。这是笔记的增值部分,不是装饰。

## 规则

- **一论文一卡**:同名论文合并,不重复建卡。
- **状态跟着阅读走**:精读完成、四节填全 → `status: 已读`(见 reading-flow.md)。
- **互链**:接项目 `[[projects/<名>]]`、接技术 `[[tech/<主题>]]`、相关论文 `related`。
- **摘要不替正文**:frontmatter `summary` 一行概述,供查询 3-tier 用;正文才记内容。
- **提炼**:读后有用的通用方法/机制,去项目化提炼进 skill 仓库(如 code-guidelines 附属文档),论文卡留指针。

## 反例

| 反例 | 问题 | 改法 |
|------|------|------|
| 抄 abstract | 没有自己的理解 | 用自己的话复述 |
| 只有"讲了什么",没有"和我有关" | 读完不接自己的问题 | 填「与我的关联」 |
| 状态标"已读"但四节空着 | 只是看完了 | 四节填全才算已读 |
